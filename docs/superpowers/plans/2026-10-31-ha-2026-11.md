# Bestiarium на HA 2026.11 — план реалізації (DEV-016)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. (Для DEV-016 бріф призначає `superpowers:executing-plans`.)

**Goal:** Mode, Devices, Climate й IR завантажуються на HA 2026.11 без помилок і без попереджень про застарілі API та працюють як раніше на HA 2026.10.4.

**Architecture:** один код для обох версій. Єдине, що в нас ламає 2026.11, — старі імена температур у двох клімат-сутностях. Кожна сутність отримує властивості `native_*`, а старе ім'я стає аліасом на ту саму властивість. Ядро 2026.11 бачить обидва імена в одному класі й не попереджає («native wins»). 2026.10, де `native_*` ще нема, читає старі. Тести ганяємо на обох версіях: дві матриці в CI, два образи в Docker локально. Сторож у `tests/conftest.py` ловить і новий вид попереджень 2026.11.

**Tech Stack:** Python 3.14, HA 2026.10.4 і 2026.11.x, `pytest-homeassistant-custom-component` (далі phacc) під кожну версію, Docker (`Dockerfile.dev`), GitHub Actions.

**Spec:** `D:\bestiarium-smart-home\handoff\DEV-016-01-brief.md`; контекст — `DEV-000-02-plan.md`, `DEV-000-04-report.md` (таблиця змін 2026.11–2026.12).

## Global Constraints

- Сутності, `unique_id`, `entity_id`, атрибути стану, налаштування записів і картка «Схема живлення» не змінюються. `VERSION`/`MINOR_VERSION` записів не чіпаємо, міграцій нема.
- Повний прогін зелений на **обох** версіях: `homeassistant==2026.10.4` і `homeassistant==2026.11.x` (реліз; для бети — див. питання 1).
- Мінімальна підтримувана версія — **HA 2026.10.4**.
- Кожен аліас старого імені — один рядок із коментарем `# HA 2026.10; drop with its support`, щоб потім знайти всі grep'ом.
- Код, коментарі, коміти — англійською; коміти `fix|test|chore|docs(<integration>): …`.
- Робочий HA не чіпаємо. Docker на змонтованому репозиторії — лише з `--user 1000:1000 -e HOME=/tmp`.

## Review Focus

1. **Термостат після перезапуску HA на 2026.11** відновлює ту саму ціль: `VirtualThermostat` читає `ATTR_TEMPERATURE` з останнього стану, `HisenseClimate` — власні extra data. Тест відновлення — у Task 3 і Task 4.
2. **Користувач у °F.** HA перераховує `native_*` у системні одиниці так само, як раніше. Наші сутності завжди в °C, тож нічого не змінюється. Тест на °F не додаю, бо це поведінка ядра, а не наша.
3. **Сервіс `climate.set_temperature` на 2026.11** проходить через нову перевірку меж `min_temp`/`max_temp` і доходить до нашого `async_set_temperature`. Тест у Task 3 і Task 4.
4. **Схеми flow під probatio** приймають ті самі значення, що й під voluptuous: порожні опційні поля, `Coerce`, селектори тривалості. Наявні тести flow на 2026.11 (Task 5). Якщо змінилися лише тексти помилок ядра — правлю очікування в тесті, не код.
5. **Запис нового значення в сутність на 2026.11 не має попереджати.** IR пише ціль під час роботи (4 місця). Сторож із Task 2 ловить «writes the deprecated» у будь-якому тесті.
